# ADR 0016：主画面实时定位预览与精确提交

- 状态：Accepted
- 日期：2026-09-09
- 范围：更新 ADR 0013、0014 的横滑、时间轴与双击定位行为

## 背景

原横滑和时间轴拖动只改变时间提示，松手后才发送原生精确定位。仅改成频繁关键帧 seek 仍受 GOP 间隔限制，每个 GOP 只有一张新画面，而且反复重置音视频输出会造成跳到新画面后再次停顿。目标是让主画面连续显示拖动经过的中间帧，松手后精确定位，并保持随后播放的连续性。

## 决定

- 横滑和时间轴共用主画面预览链路。Android 自动解码模式下，本地 `content` / `file` 媒体优先使用独立 `MediaExtractor` / `MediaCodec` 解码视频。前向邻近目标连续解码，反向命中缓存；跨区间才回到前一个关键帧重新解码。请求和发布均合并到最新目标。
- GPU 把预览缩小到长边 480 像素的 SDR RGBA8 bitmap，缓存最多 80 帧、采样间隔约 150 毫秒媒体时间。预览覆盖在主视频相同的 FIT / FILL / STRETCH 几何区域内，不新增缩略图界面。服务先通过 `BEGIN` 获取预览租约，核心执行 `SetPlaybackSuppressed(true)` 暂停主播放器，保留用户的 `playWhenReady` 意图；收到确认后才启动独立解码。Media3 对外报告 `PLAYBACK_SUPPRESSION_REASON_SCRUBBING`。预览位置不写入历史。
- 快速同向扫动时，每次前景解码按拖动速度获得 250–1,000 毫秒工作窗口，再按超过 3 秒媒体距离丢弃过时目标，避免反复 flush 而无画面。约 10 倍浏览允许长 GOP 解码工作到 1 秒，约 40 倍快速扫动收紧为 250 毫秒。改变方向、释放或关闭仍立即取消；反向预取只在当前目标未变化时工作，新的任一方向输入立即抢占。快速拖动允许跳过部分画面并落后于目标，提交仍为一次精确定位。
- HDR、BT.2020、非零旋转、非方形像素、软件解码偏好、非本地来源或独立解码失败时，回退为原生关键帧预览，每 80 毫秒最多发送一次。独立预览不绘制外挂字幕；松手后主视频恢复原画质、色彩处理和字幕。
- 松手关闭独立解码，只保留最后一张预览，向主播放器提交一次精确定位。`SeekCompleted` 带有可选的请求关联 ID；服务验证引擎、媒体、队列代际、播放意图和 ID 后释放临时抑制，仅在用户仍要求播放时恢复，然后完成提交 future。界面跨两个动画帧边界，再做有期限的 1 × 1 `PixelCopy` 缓冲探测后撤去预览。探测只证明 Surface 有可读取缓冲，目标帧身份仍依赖原生关联完成；它不等于屏幕光学呈现证明。Surface 代际变化使旧回调失效。暂停时也能完成，不依赖下一次正常播放帧。生命周期暂停等待已发出的提交/取消 future，避免后发 Pause 抢先使精确位置失效。
- 主视频改用 `SurfaceView`，保持 libmpv、MediaCodec 硬解和 libass 字幕链路。Surface 由 `SurfaceHolder` 持有，应用只绑定/解绑，不主动释放它；沿用固定原生缓冲尺寸与 FIT / FILL / STRETCH 布局。使用默认图层顺序，让控件和预览 ImageView 位于视频上方。重绘使用 `surfaceRedrawNeededAsync`，在重绘请求、UI 帧边界及缓冲探测后完成；销毁和超时也确保每个回调只完成一次。Surface token 在异步绑定执行时再次核对。
- 侧边双击只发出一次精确的加减 5 秒定位。目标从事件发生时的 Media3 位置计算，保留其同步位置掩码，使尚未收到状态回调时的连续双击仍能累计。中央双击、长按变速和竖滑行为保持原有规则。
- 正常取消时精确恢复操作前位置，再按原播放意图解除临时抑制；生命周期 `ABORT`、断连、拖动中的音频焦点丢失均恢复未提交预览的原位并保持暂停。已提交的位置不因随后失焦回滚。新的播放意图、停止、换媒体、外部 seek 终止旧操作；已退休 token 不能重新开始预览。服务的提交期限包含前一个在途 seek 的等待，期限到达后在同一操作锁内清 pending 并显式暂停，迟到完成不能重新播放。解码器及 EGL 资源在同一专用线程创建、使用和关闭，迟到回调不能重新发布已取消画面。
- Android 服务接收仅限同 UID 的 `SeekPreviewContract`，校验控制器、token、媒体 ID、请求序列、队列索引、引擎代际与播放意图。队列修改和预览按同一顺序执行。失效状态直接丢弃，失败时释放操作；断连退休不依赖可能被队列替换跳过的任务。
- 共享核心增加默认值为 `EXACT` 的 `SeekPrecision`，不引入 Android 类型。原生调用仍保持单个在途请求和一个最新待处理请求；合并时保留精度，不能因乐观位置相同而丢掉预览后的精确提交。定位完成有 10 秒期限，缺失完成信号进入 RESET 恢复路径，避免永久阻塞后续定位。
- mpv 预览使用 `absolute+keyframes`；精确定位使用可写的 `time-pos`，并在初始化时设定 `hr-seek=absolute`。锁定版本的属性写入走不带 `MPSEEK_FLAG_DELAY` 的绝对定位，同时保持精确解码。关键帧间隔与硬件解码成本仍然存在。
- 原生完成关联采用有序的 `MPV_EVENT_SEEK` 和 `MPV_EVENT_PLAYBACK_RESTART`。不再用可能被合并的 `seeking` 属性通知决定完成；未收到当前 SEEK 的旧 RESTART 无效。
- Android 本地可定位的普通文件，通过元数据确认所有音轨均为单/双声道、8–192 kHz 后，优先使用 `opensles,audiotrack` 输出。此设备的 AudioTrack 输出在首个新画面后有约 160 毫秒重启等待，OpenSL ES 的对应间隔约 42–52 毫秒。多声道、参数未知、管道和其他来源保持 `audiotrack,opensles`。初始化失败可用后备输出；不承诺运行中路由切换自动回退或所有设备都有同样收益。探测恢复文件描述符偏移，并保留原借用生命周期。
- 缓冲指示器在连续等待 400 毫秒后显示，短暂定位不闪现指示器，持续加载仍有反馈。进度每 100 毫秒轻量更新，队列和轨道列表由 Media3 事件更新，避免加快采样时反复重建列表。

## 验证与限制

单元测试覆盖预览与精确请求合并、同目标提交、带关联 ID 的完成、过时事件、完成超时、临时抑制及播放意图覆盖。真机使用原创帧编码视频，窗口 `PixelCopy` 读取独立预览覆盖层，SurfaceView 主视频直接读取其生产缓冲；完整屏幕截图另行核对合成、字幕与旋转。帧率基准使用真实 Choreographer，不使用 Compose Test 的受控时钟。控制器的乐观位置和预览状态更新次数不作为出帧证据。

设备用例覆盖横滑、时间轴、快速连击、取消、暂停/播放保持、旧 token/媒体序列、停止重播和断连。用户指定的 1080p Main10 HEVC / FLAC 文件另有私有后端更新间隔基准，以及通过未注册的唯一媒体 ID 进行的主界面预览基准，后者不经媒体注册器，也不更新个人记录。历史测量见[首次连续预览验证](../validation/2026-09-09-live-seek-preview.md)，本次改动见[暂停主播放与 SurfaceView 验证](../validation/2026-09-09-scrub-suppression-and-surfaceview.md)。首次建立独立解码器、长 GOP 精确定位仍需要时间；单台设备结果不代表网络媒体、HDR、多声道和其他设备表现。
